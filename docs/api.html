C API

C API reference

The headers in include/erps/ are the reference; this page explains how the pieces fit. All functions return erps_err_t (0 on success) unless noted.

Contract

  • One erps_t is one ERP instance on one node. Distinct instances are independent.
  • Time is an input: every call takes now, a monotonic clock in microseconds (erps_time_t) with an arbitrary origin. A time earlier than a previous call is clamped and counted in clock_backwards.
  • An instance is not thread-safe. Serialise calls to it, typically from one event loop.
  • Callbacks run synchronously inside the call that caused them. They must not call back into the same instance (refused with ERPS_E_BUSY); erps_destroy() from a callback is deferred safely.
  • The library never blocks, sleeps or reads a clock, and allocates only in erps_create().

Inputs and time

FunctionPurpose
erps_rx_frame(e, port, frame, len, now)A received frame with its 802.1Q tag. Returns ERPS_OK if accepted as an R-APS for this instance, ERPS_E_DROPPED if the validity check discarded it (reason counted).
erps_rx_pdu(e, port, &meta, pdu, len, now)The same for platforms that strip the Ethernet header or tag: meta carries destination, source, VID and PCP.
erps_set_signal_fail(e, port, ssf, now)Ring-port signal fail (carrier, CCM). SF is declared after the hold-off time if still present; clearing is immediate.
erps_command(e, cmd, port, now, &why)ERPS_CMD_FORCED_SWITCH, _MANUAL_SWITCH (with a port) or _CLEAR. Returns ERPS_E_REJECTED with an erps_reject_t when the local priority logic refuses it.
erps_poll(e, now)Fire due timers and transmissions, in deadline order.
erps_next_deadline(e)The time by which erps_poll() must be called, or ERPS_TIME_NEVER.
erps_send_flush_event(e, now)Send a burst of three R-APS Event (flush) messages, for diagnostics and interop tests.

Command rejections: COMPAT_V1 (FS or MS in compatible-version 1), FS_ACTIVE (a local FS exists), HIGHER_PRIORITY (local SF or FS outranks an MS), MS_IN_RING (an MS, FS or SF already exists in the ring), CLEAR_NOT_APPLICABLE, NOT_RUNNING.

Introspection

erps_status_t st;   erps_get_status(e, &st);     /* state, ports, top request, timers, Tx message, FOP */
erps_counters_t c;  erps_get_counters(e, &c);    /* per port and kind Rx/Tx, drops by reason, flushes  */
erps_trace_t h[32]; size_t n = erps_get_history(e, h, 32);   /* oldest first */
uint8_t rows[9];    erps_get_row_coverage(e, rows);  /* bit r = Table 10-2 row r has run */

int need = erps_dump(e, ERPS_DUMP_ALL, ERPS_FMT_JSON, NULL, 0);   /* snprintf semantics */
char line[256];     erps_trace_format(&h[0], line, sizeof line);

A history entry records the time, the triggering request (R-APS node ID, BPR and receiving port), the state transition, the Table 10-2 row, the actions in order and the port states before and after:

#4 t=301.001050 A->B row 7 R-APS(SF) 02:00:00:00:00:03 bpr0 @p0 [unblock-p1 stop-tx] ports -B->--

Every enum has a name function (erps_state_str, erps_req_type_str, erps_drop_str, erps_reject_str, erps_strerror, …) and messages and requests have formatters (erps_raps_msg_format, erps_req_format).

Several instances: erps_mgr

A node usually runs several ERP instances on the same ring ports, each with its own R-APS VID and VLAN set. The manager owns them and does what an event loop needs:

erps_mgr_t *m = erps_mgr_create();
erps_mgr_add(m, &cfg, &ops, user, &e);           /* names unique; (ring ID, VID) unique per port */
erps_mgr_rx_frame(m, port_handle, frame, len, now); /* demultiplex by port, VID and ring ID */
erps_mgr_set_signal_fail(m, port_handle, ssf, now); /* fan out to every instance on the port */
erps_mgr_poll(m, now);
erps_time_t next = erps_mgr_next_deadline(m);

R-APS codec: erps_pdu.h

The codec the core uses is public, for adapters and tools: erps_eth_parse() (up to two VLAN tags), erps_pdu_decode() (length, opcode 40, TLV offset, request and event validity), erps_pdu_encode(), erps_frame_encode() (a tagged frame padded to 60 octets), erps_raps_dmac(), erps_msg_kind() and erps_node_id_cmp().
